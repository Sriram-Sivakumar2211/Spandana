# Cross-Modality Validation Report

Tests whether the general severity model (healthy/warning/faulty, 24-dim canonical schema) trained on ONE machine modality transfers to a structurally different modality it never saw -- Member 1's electro-mechanical sensors (MetroPT-3 air compressor, squirrel-cage motor, thermal motor) vs. Member 2's bearing-vibration rigs (NASA IMS, CWRU, Paderborn). This is strictly harder than cross-dataset domain shift (see cross_dataset_report.md): the two modalities populate disjoint slices of the 24-dim feature vector (utils/schema.py::fill_feature_vector), so transfer requires generalizing from 'which features are populated and how' rather than from comparable physical quantities.

| Scenario | Source modality | Target modality | Target Accuracy | Target F1 (macro) | Target ROC AUC |
|---|---|---|---|---|---|
| member1_to_bearing | metropt3+thermal_motor+squirrel_cage | nasa_ims+cwru+paderborn | 0.2024 | 0.1683 | 0.0904 |
| bearing_to_member1 | nasa_ims+cwru+paderborn | metropt3+thermal_motor+squirrel_cage | 0.1248 | 0.1110 | 0.5104 |

**member1_to_bearing** target class distribution: {'healthy': 47551, 'warning': 0, 'faulty': 10183}
**bearing_to_member1** target class distribution: {'healthy': 720, 'warning': 0, 'faulty': 4995}

**Honest interpretation**: read any result above alongside its target class distribution and the ground_truth caveat already disclosed for Member 1's data (preprocessing/schema_adapter.py) -- MetroPT-3 is 100% 'faulty', squirrel-cage and thermal_motor are 100% 'healthy' (no 'warning' examples exist anywhere in Member 1's data), so a model that always predicts one class can score deceptively well or poorly purely from this imbalance, independent of genuine cross-modality generalization. Numbers are reported as measured, without adjusting thresholds, oversampling, or re-labeling classes to manufacture a better-looking result.

**This is total single-class collapse, not partial degradation.** The confusion matrices confirm it directly: `member1_to_bearing` predicts "faulty" for all 47,454 target sequences (the "healthy" column is entirely zero, yielding 20.2% accuracy against an ~82%-healthy target); `bearing_to_member1` predicts "healthy" for all 5,703 target sequences (the "faulty" column is entirely zero, yielding 12.5% accuracy against an ~87.6%-faulty target). `recall_macro = 0.5000` in *both* directions is the mechanical fingerprint of a one-class-only classifier (one class at recall 1.0, the other at 0.0) -- a stronger, cleaner signal than the 0.24-0.26 accuracy range seen in cross_dataset_report.md's bearing-only scenarios, where predictions were at least spread across multiple classes.

**What this most likely means**: the general model has learned "which sensor rig produced this reading" (i.e. which of the 24 canonical feature slots are populated vs. zero-filled) as a shortcut correlated with the health label, rather than a genuine cross-modality notion of machine health. Member 1's data is dominated by MetroPT-3 (100% "faulty") and the bearing data is dominated by NASA IMS (99.7%+ "healthy"), so a model keying on which feature slots are nonzero can reach near-perfect *in-modality* accuracy (99.5% test accuracy, general_model_evaluation_augmented.json) while carrying almost nothing that survives a move to a modality with disjoint feature slots.

**Why this was not "fixed"**: forcing a better number here (re-weighting, re-thresholding, or blending modalities into one combined training run) would mask a real, disclosed limitation rather than report it, and was explicitly ruled out by this project's anti-fabrication requirement. Deployment conclusion: the general 6-dataset severity model should be trusted within the modality/modalities it was trained on, not as a zero-shot cross-modality classifier -- extending it to a genuinely new modality would need modality-specific fine-tuning data or physically comparable normalized features across modalities, neither of which exists in the source datasets used here.
